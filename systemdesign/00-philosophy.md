# 00 — Brand Philosophy

**Precision over personality.** Every token has a named job. Every component answers a specific product need. The system must hold its own in a procurement slide deck next to Stripe, Linear, Vercel, and Anthropic — those are the comparables enterprise buyers will use.

## What v3 fixed (from v1/v2)

| v1 / v2 — what was wrong | v3 — what is fixed |
|---|---|
| Dual primaries (blue + amber) | Single primary (blue). Amber is **accent only** — pricing, upgrade, premium tier |
| Emoji icons | 24-icon Lucide-compatible SVG sprite |
| DM Sans | Sora (display) + Inter (UI) + JetBrains Mono (code) |
| Dark-only palette | Full light + dark token sets, theme switch via `data-theme` |
| No data table component | Canonical data table defined |
| No sidebar nav | Product sidebar pattern defined |
| No skeleton or empty states | Both defined for all clusters |

## Reference companies

If a UI would look out of place next to **Linear / Stripe / Vercel / Anthropic** in a side-by-side procurement comparison, it does not ship.

## Why this matters

The company is transforming from a services agency (18 service lines, project-based revenue) into an enterprise software company (5 SaaS clusters, recurring revenue). The visual language has been rebuilt from first principles to support product surfaces, not service brochures. The buyer is an enterprise procurement function, not an SME marketing team — every visual decision should be evaluated against that audience.
