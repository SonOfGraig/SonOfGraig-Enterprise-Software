Why the Creative & XR Studio exists

A design system without a brand identity is incomplete.
A brand identity without spatial extension is stuck in 2D.

South African design teams pay for Figma, then for a separate component library, then for an accessibility scanner, then for an asset generator, then for an AR vendor — usually all in dollars, none of them speaking to each other. Cluster 04 collapses that stack into one experience layer.

01 — Design system fragmentation

Brand tokens live in Figma. Components live in code. They drift.

Designers ship a Figma library. Developers rewrite the components. Three months later the brand colour shifts a hex, the spacing scale changes, and nobody knows which one is canonical. Every new product reinvents the system.

~40% of front-end engineering time spent rebuilding components that already exist somewhere in the org.
02 — Accessibility as afterthought

WCAG audits happen at launch. Fixes are ten times more expensive then.

Accessibility scanners are bought as standalone tools that run after design and after build. By the time a contrast issue is caught, the design has shipped to staging. POPIA's right-to-equal-access provisions only deepen the obligation.

10× cost of fixing an a11y bug in production vs. catching it at design-token level.
03 — Brand asset bottlenecks

Marketing wants 50 ad variants on Friday. The studio has time for 5.

Performance marketing requires hundreds of creative variants. Every variant runs through the same approval queue. Generative AI promises scale but breaks brand guardrails the moment a junior creator gets a token.

15× throughput uplift when generative output is gated behind brand guardrails — instead of free-form prompting.
04 — XR locked behind specialists

A VR training simulation needs Unity. A virtual showroom needs Unreal. You need neither hire.

South African retail, training, and architecture teams want spatial experiences but cannot justify a Unity team. Existing XR vendors are priced for global enterprises and ship dollar-denominated. The build-vs-buy gap is huge.

R750k+ typical custom Unity training simulation quote from a SA agency — before content.

Accessibility built in, not bolted on

Three audit questions every digital team gets asked.
The Studio answers them at design time.

POPIA's right-to-equal-access provisions mean accessibility is not optional in South African enterprise. WCAG 2.2 AA is the floor — many regulated sectors (banking, government, education) require AAA. Cluster 04 was designed so accessibility is enforced at the token level, before a single line of production code ships.

What is the contrast on this button?
Every colour token in the graph is scored against WCAG 1.4.3 (AA) and 1.4.6 (AAA) at the moment it's defined. Failing combinations are flagged in the design tool — not at code review.
→ Design System Generator · Token contrast lint
Can a keyboard user complete this flow?
Components ship with focus order, focus traps, skip-links, and visible focus indicators baked in. The CI gate runs a keyboard-only walkthrough on every PR — flows that fail are blocked from merge.
→ Accessibility Checker · CI keyboard simulation
What does a screen reader hear?
Preview the announced output for NVDA, JAWS, and VoiceOver from inside the design tool. ARIA labels, landmarks, and live-region announcements are auto-suggested from the component schema.
→ Accessibility Checker · Screen-reader preview
WCAG 2.2 coverage by component

Every component in the library declares its WCAG conformance level. Components without AAA conformance are clearly marked — and the Checker proposes the token changes needed to lift them.

Component AA AAA Notes
Button (primary) Pass Pass Min target 44×44, contrast 7:1
Input field Pass Pass Label associated, 5px focus ring
Modal Pass Partial Reduced-motion variant required
Data table Pass Pass Headers + scope + summary
Toast / notification Pass Partial aria-live=polite, dismissible
Carousel Pass Partial Pause control, reduced-motion respect
